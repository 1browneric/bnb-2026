STEP 3 -- VOR (this is the whole edge -- do not skip or approximate)
=====================================================================
Rank on value over replacement, NEVER on projected points.

Derive replacement level from MY league, do not use a rule of thumb and do not copy
numbers from anyone else's league:
  a. Count every starting skill slot in the league: teams x slots.
  b. Walk the projection board top down, assigning each player to a slot he is eligible
     for, until every one of those slots is full.
  c. Replacement level per position = the best player left over.
  d. Report the resulting baselines to me (e.g. "QB13, RB30, WR36, TE11") so I can sanity
     check them. They move a LOT with team count and roster format.

VOR = projected points - replacement level for that position.

Then, for recommendations, use MARGINAL value, not raw VOR:
  FILL = one replacement-level dummy per starting slot, EACH WITH A UNIQUE NAME
  def marginal(player, roster):
      return lineup(roster + [player] + FILL).total - lineup(roster + FILL).total
Without this, an empty starting slot makes every player at that position look worth his
entire projection, and the tool will recommend nothing but quarterbacks.

STEP 7 -- LIVE UPDATING
=====================================================================
Architecture -- the page must NEVER call the Yahoo API directly:

  Yahoo API  ->  poller (own process, every 5s)  ->  feed.json
                                                        |
                 local web server (python3 -m http.server) serves page + feed.json
                                                        |
                 page fetches feed.json every 6s, re-renders in place, no reload

Why: Yahoo sends no permissive CORS headers, the OAuth token must never appear in a page
anyone can view source on, and a bad API response should corrupt one small file rather than
the ranked board.

Rules:
  - The board and projections are baked into the HTML ONCE before the draft. feed.json
    carries ONLY who-took-whom. Keep them separate.
  - Write feed.json atomically: write feed.json.tmp then os.replace(). Otherwise the browser
    eventually reads a half-written file and throws mid-draft.
  - Guard the poller so the page still works opened as a plain file:
      if(!/^https?:$/.test(location.protocol)) return;
  - Browsers throttle timers to ~1 per minute in a hidden tab. Also refresh on
    visibilitychange and focus, or flipping back from the draft room shows a stale board.
  - On a dead feed, keep the last good board on screen and show FEED DOWN. Never blank it.
  - Give me ONE command that starts the poller and the server and prints the URL.

STEP 8 -- FIFTEEN THINGS THAT WILL BREAK (these all actually happened)
=====================================================================
Most of these produce a confidently WRONG answer rather than an error. Handle every one and
tell me you did.

 1. A name regex requiring two consecutive letters before a space silently drops A.J. Brown,
    D.J. Moore, T.J. Hockenson. Test against every punctuation style.
 2. HTML table parsers glue team codes onto names: "KC Kenneth Walker III" becomes a second,
    draftable copy of a rostered player. Strip a leading team abbreviation ONLY when what
    remains still has two name tokens -- otherwise you rename KC Concepcion.
 3. Nicknames create duplicate players: Kenny/Kenneth Gainwell, Chig/Chigoziem Okonkwo,
    Josh/Joshua Palmer. Merge on surname + position + team where one first name is a prefix
    of the other or a known nickname. Do NOT merge on first initial: Bijan Robinson and
    Brian Robinson Jr. are two different Atlanta running backs.
 4. Replacement-level filler players must have UNIQUE names. If they share a name the lineup
    builder dedupes them and every marginal calculation is silently wrong.
 5. Defenses never match by name -- the feed says "Texans"/"HOU", projections say "Houston
    Texans". Match defenses on team code and assert all 32 resolve.
 6. Print pick labels as round + IN-ROUND pick zero-padded ("4.06"), not round + overall
    ("4.30"). And if anything SORTS by parsing that label, fix it too -- a log sorted that
    way came out 1.01, 2.01, 3.01, 1.02.
 7. A CSS rule like .modal{display:flex} overrides the browser's [hidden]{display:none} and
    the close button does nothing. Add .modal[hidden]{display:none}.
 8. An absolutely positioned tooltip inside an overflow-x:auto table gets clipped to the row
    height. Use one fixed-position tooltip element on the body.
 9. Printing "current best available" on every round card names the same player in rounds 1
    through 6. Remove expected market takes per pick AND carry a running exclusion set.
10. Keep manual overrides in a separate namespace from feed state and rebuild feed state
    from scratch every poll, so a corrected feed self-heals. Stale localStorage from testing
    will otherwise follow you into the real draft.
11. Do not make table rows clickable to mark players drafted. Far too easy to hit by accident
    while scrolling on a clock. If the feed works, manual marking is not needed.
12. Scan for AVAILABILITY, not just injuries -- suspensions, commissioner exempt list,
    holdouts, trades, releases, depth-chart changes. Run each as its own search. No injury
    search will ever surface a legal suspension.
13. Flagging is not deciding. Show the status, never block the pick. An unavailable player is
    still draftable as a stash and that call is MINE, not the tool's.
14. Encode the player board columnar -- a key list plus flat rows rebuilt at load -- not as an
    array of objects. Repeated key names were 57% of the payload. But profile first: if every
    render is under 20ms, runtime is not your problem.
15. Never patch generated code with a blind str.replace(). Assert the anchor exists before
    replacing, then grep the built output to confirm. A silent no-op reports success and a
    bad slice deletes render functions nobody notices for an hour.
